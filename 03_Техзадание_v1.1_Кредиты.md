## 1. Зачем

Сейчас кредит — просто строка чек-листа платежей: имя, день срока, сумма, галочка. Семье нужен **реестр кредитов**: сколько ещё должны по каждому и всего, сколько платежей осталось и когда какой закроется, какая переплата, плюс справочные реквизиты (банк, № договора, дата открытия, назначение).

Принцип: пользователь один раз вводит данные из договора, дальше приложение считает всё само по уже существующим отметкам оплат (`obligation_payments`). Никакого дублирующего ввода.

## 2. Модель данных

Новая таблица `credits` — расширение обязательства типа `credit`, связь 1:1:

```sql
CREATE TABLE IF NOT EXISTS credits (
  id SERIAL PRIMARY KEY,
  obligation_id INTEGER NOT NULL UNIQUE REFERENCES obligations(id),
  bank TEXT NOT NULL,                    -- «Сбер», «Тинькофф»…
  contract_number TEXT,                  -- № договора (справочно)
  opened_date TEXT,                      -- 'YYYY-MM-DD' дата открытия (справочно)
  purpose TEXT,                          -- назначение: «ремонт», «телефон»…
  principal INTEGER NOT NULL CHECK (principal > 0),      -- взяли (тело), копейки
  total_payout INTEGER NOT NULL CHECK (total_payout >= principal), -- всего вернёте по графику, копейки
  months_total INTEGER NOT NULL CHECK (months_total > 0),          -- срок: число платежей
  payments_before INTEGER NOT NULL DEFAULT 0 CHECK (payments_before >= 0), -- платежей внесено ДО начала учёта в «Очаге»
  rate_percent REAL,                     -- ставка % годовых, опционально, чисто справочно
  CHECK (payments_before <= months_total)
);
```

Решения (не обсуждать, выполнять):
- **Переплата = `total_payout − principal`.** Ставку НЕ использовать в расчётах — только показывать, если введена. Оба числа есть в любом договоре/графике, это точнее самодельного аннуитета.
- **«Осталось выплатить» = `total_payout − выплачено»**, где `выплачено = payments_before × default_amount (обязательства) + Σ фактических сумм obligation_payments этого обязательства`. Это бытовое «сколько я ещё должен» — остаток тела по аннуитетной формуле НЕ считать (вне объёма).
- Деактивация обязательства (`is_active = 0`) скрывает кредит из реестра вместе со строкой чек-листа. Отдельного удаления credits не нужно.
- Миграция выполняется тем же механизмом, что и существующая (`CREATE TABLE IF NOT EXISTS` в `db.ts`). Существующие обязательства kind='credit' без записи в `credits` валидны: показываются в чек-листе как раньше, в реестре «Кредиты» — в блоке «Без данных договора» с кнопкой «Заполнить».

## 3. Расчёты — чистые функции в `server/src/core/logic.ts` (+ тесты vitest)

```ts
export interface CreditInfo {
  monthly: number;          // default_amount обязательства
  principal: number;
  totalPayout: number;
  monthsTotal: number;
  paymentsBefore: number;
  paidTx: number[];         // фактические суммы obligation_payments (копейки)
}

export interface CreditCalc {
  paymentsMade: number;     // payments_before + paidTx.length
  paymentsLeft: number;     // max(0, monthsTotal − paymentsMade)
  paidSum: number;          // paymentsBefore*monthly + Σ paidTx
  leftToPay: number;        // max(0, totalPayout − paidSum)
  overpay: number;          // totalPayout − principal
  progress: number;         // clamp(paymentsMade / monthsTotal, 0, 1)
  closeMonth: string | null;// 'YYYY-MM' — месяц последнего платежа, null если paymentsLeft = 0
}

export function creditCalc(c: CreditInfo, todayMonth: string): CreditCalc
```

`closeMonth`: если в `todayMonth` платёж по этому кредиту ещё не отмечен — он считается первым из оставшихся, тогда `closeMonth = todayMonth + (paymentsLeft − 1) месяцев`; если уже отмечен — `closeMonth = todayMonth + paymentsLeft месяцев`. Вычисление сдвига месяцев — без `new Date()` без аргументов (правило §4 базового ТЗ действует).

Обязательные тест-кейсы: обычный кредит в середине срока; кредит с `payments_before > 0`; полностью выплаченный (`paymentsLeft = 0`, `progress = 1`, `closeMonth = null`); фактические оплаты, отличающиеся от плановой суммы (paidSum по фактам); кейс «в текущем месяце уже оплачен» против «ещё не оплачен» для `closeMonth`; переплата 0 (`total_payout = principal`).

## 4. API

| Метод и путь | Назначение |
|---|---|
| `GET /api/credits?today=YYYY-MM-DD` | Реестр: `{ summary: { totalLeftToPay, monthlyLoad, count }, items: [...] }`. `monthlyLoad` = Σ default_amount активных кредитов с paymentsLeft > 0. Каждый item: поля obligation + credits + результат `creditCalc` + `noData: true` для кредитов без записи в credits (у них только имя/сумма/день). Сортировка: ближайший к закрытию первым |
| `PUT /api/obligations/:id/credit` | Создать или обновить данные договора (upsert по obligation_id). Тело: `{ bank, contractNumber?, openedDate?, purpose?, principal, totalPayout, monthsTotal, paymentsBefore?, ratePercent? }`. 400 с русским сообщением, если обязательство не существует, не активно или kind ≠ 'credit' |

Существующие эндпоинты не менять. Поля валидировать zod в стиле существующих роутов; новый файл `server/src/routes/credits.ts`, регистрация в `app.ts`.

## 5. Экран «Кредиты»

Точка входа: на вкладке «Платежи» под сводкой — карточка-кнопка «Кредиты: осталось выплатить N ₽ →» (показывается, только если есть активные обязательства kind='credit'). Ведёт на `/credits`. В нижнюю навигацию НЕ добавлять (4 вкладки — закон).

`/credits` (новый экран `web/src/screens/Credits.tsx`):
1. **Сводка сверху:** «Всего осталось выплатить **X ₽** · в месяц **Y ₽** · кредитов N». Крупная цифра X — кеглем главной суммы, цвет Уголь (не Кирпич: долг — это быт, а не тревога).
2. **Карточка кредита** (по существующим токенам: rounded-card, shadow-card):
   - имя + банк, под ними мелким Дымом: «№ договора · открыт 12 марта 2024 · ремонт» (только заполненные поля);
   - полоса прогресса (стиль полос из «Итогов», цвет Хвоя): подпись «выплачено 14 из 36»;
   - строки: «Осталось выплатить — N ₽», «Платежей осталось — K, закроется в марте 2028», «Платёж — M ₽ до 25-го», «Переплата по договору — P ₽» (+ «ставка R %», если введена);
   - статусная точка текущего месяца как в чек-листе (оплачен/скоро/просрочен) — данные уже есть в bills, можно передать или запросить.
3. Кредиты с `noData` — отдельным блоком внизу: имя + кнопка «Заполнить данные договора».
4. **Форма данных договора** (BottomSheet, открывается с карточки «Изменить» и из noData-блока): банк*, № договора, дата открытия (date input), назначение, взяли (₽)*, всего вернёте по графику (₽)*, срок в платежах*, уже внесено платежей до «Очага» (по умолчанию 0), ставка % (опционально). Подсказка под формой: «Эти числа есть в договоре или графике платежей». Суммы вводятся в рублях, конвертация в копейки как в остальном коде.
5. Состояния: скелетоны, ошибка сети с «Повторить», пусто («Добавьте кредит на вкладке Платежи — он появится здесь») — в тоне брендбука.

Словарь: «Осталось выплатить», «Переплата», «Закроется в …», «Выплачено X из Y». Без слов «задолженность», «остаток основного долга».

## 6. Что НЕ входит (не реализовывать)

Аннуитетный расчёт остатка тела; графики платежей по месяцам; досрочное погашение и пересчёт; напоминания; редактирование `obligation_payments` отсюда (только из чек-листа); удаление таблицы credits из экспорта — наоборот, **добавить `credits` в TABLES экспорта/импорта** (`routes/data.ts`) с сохранением порядка зависимостей (после obligations).

## 7. Приёмочные критерии

1. Миграция на существующей базе с данными проходит без ошибок; старые кредиты видны в реестре как «Без данных договора».
2. Кредит: взяли 300 000 ₽, вернуть 390 000 ₽, 36 платежей по 10 833 ₽, до «Очага» внесено 10, в «Очаге» отмечено 4 оплаты (одна — фактом 11 000 ₽) → карточка показывает «выплачено 14 из 36», paidSum = 10×10 833 + сумма фактов, «осталось выплатить» = 390 000 − paidSum, переплата 90 000 ₽, closeMonth корректен относительно того, оплачен ли текущий месяц.
3. Отметка оплаты в чек-листе сразу (после инвалидации запроса) меняет цифры на `/credits` без перезагрузки.
4. `PUT .../credit` для обязательства kind='utilities' → 400 с русским сообщением.
5. Экспорт → импорт сохраняет данные кредитов.
6. Все тест-кейсы §3 зелёные (`npm test`).
7. Ни одной англоязычной строки в UI; суммы tabular-nums с тонким пробелом.
