## 1. Цель и контекст

Самостоятельно размещаемое (self-hosted) PWA для ведения семейного бюджета **ровно двумя** пользователями: «Он» (`him`) и «Она» (`her`). Размещается на внешнем хостинге (VPS, Docker), доступ с iPhone (Safari) и Android (Chrome) через интернет. Полноценной авторизации нет, но, поскольку приложение публично доступно, вход защищён **одним общим семейным кодом** (раздел 7.6) и работает только по HTTPS. Язык интерфейса — русский. Валюта — одна на всё приложение, символ задаётся в настройках (по умолчанию `₽`). Ориентир сумм: типовые операции — сотни и тысячи рублей, доходы — единицы тысяч; интерфейс при этом обязан корректно отображать суммы до миллионов (копилка растёт).

Критерий качества №1: **внесение траты — не более 5 секунд** от открытия приложения (последовательность: «+» → сумма → касание категории).

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Повседневные | Личный кошелёк-остаток каждого пользователя на ежедневные траты |
| Распределение | Разнесение пришедшего дохода на: в копилку / отложено на платежи / в повседневные |
| Платежи (обязательства) | Повторяющиеся ежемесячные платежи (кредиты, связь, коммуналка, интернет) — чек-лист месяца, **не** кошелёк |
| Копилка | Общий накопительный остаток семьи; снятие всегда с текстовой целью |
| Перевод | Передача суммы из повседневных одного супруга в повседневные другого |
| День зарплаты | Рассчитанная дата ближайшей выплаты пользователя (раздел 7.1) |

## 3. Технологический стек (фиксирован, не заменять)

- **Backend:** Node.js ≥ 20, **Fastify** (+ `@fastify/rate-limit` для проверки кода), **better-sqlite3** (синхронный SQLite), **zod** для валидации тел запросов. Без ORM.
- **Frontend:** **React 18 + TypeScript + Vite**, **Tailwind CSS**, **@tanstack/react-query** (серверное состояние), **react-router-dom**, иконки **lucide-react**. Без Redux/Zustand — локального состояния React достаточно.

## 4. Соглашения о данных

- **Все суммы — целые числа в минимальных единицах (центах).** В API и БД только integer. Форматирование в валюту — только на фронте.
- Даты — строки `YYYY-MM-DD`, месяц — `YYYY-MM`. **Правило часового пояса (критично, сервер на хостинге живёт в UTC):** понятие «сегодня» определяет ТОЛЬКО клиент. Все создаваемые записи получают дату от клиента; все эндпоинты, чья логика зависит от текущей даты (`/api/state`, `/api/bills`), принимают обязательный параметр `today=YYYY-MM-DD`. На сервере запрещено использовать `new Date()` для бизнес-логики (только для имён файлов бэкапа). В docker-compose дополнительно выставить `TZ=Europe/Riga` как страховку. Библиотеки таймзон не использовать.
- ID — `INTEGER PRIMARY KEY AUTOINCREMENT`. Пользователи — строковый enum `'him' | 'her'`.
- Удаление записей движения денег (траты, доходы, переводы, операции копилки) — жёсткое (DELETE), допустимо: данные семейные, аудит не нужен. Обязательства — мягкое (`is_active = 0`).

## 5. Схема БД (выполнить как миграцию при старте, `PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;`)

```sql
CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY, value TEXT NOT NULL );
-- ключи: currency_symbol ('₽'), payday_him ('[19]'), payday_her ('[10,25]') — JSON-массивы дней месяца

CREATE TABLE IF NOT EXISTS categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL, icon TEXT NOT NULL,          -- имя иконки lucide
  sort INTEGER NOT NULL DEFAULT 0, is_active INTEGER NOT NULL DEFAULT 1 );

CREATE TABLE IF NOT EXISTS incomes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user TEXT NOT NULL CHECK (user IN ('him','her')),
  date TEXT NOT NULL, source TEXT NOT NULL,         -- 'salary'|'advance'|'nails'|'other'
  amount INTEGER NOT NULL CHECK (amount > 0),
  to_daily INTEGER NOT NULL DEFAULT 0,
  to_savings INTEGER NOT NULL DEFAULT 0,
  to_bills INTEGER NOT NULL DEFAULT 0,
  comment TEXT,
  CHECK (to_daily + to_savings + to_bills = amount) );

CREATE TABLE IF NOT EXISTS expenses (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user TEXT NOT NULL CHECK (user IN ('him','her')),
  date TEXT NOT NULL,
  amount INTEGER NOT NULL CHECK (amount > 0),
  category_id INTEGER NOT NULL REFERENCES categories(id),
  comment TEXT );

CREATE TABLE IF NOT EXISTS transfers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  from_user TEXT NOT NULL CHECK (from_user IN ('him','her')),
  to_user TEXT NOT NULL CHECK (to_user IN ('him','her')),
  date TEXT NOT NULL, amount INTEGER NOT NULL CHECK (amount > 0),
  comment TEXT, CHECK (from_user <> to_user) );

CREATE TABLE IF NOT EXISTS savings_tx (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL CHECK (type IN ('deposit','withdrawal')),
  user TEXT NOT NULL CHECK (user IN ('him','her')),
  date TEXT NOT NULL, amount INTEGER NOT NULL CHECK (amount > 0),
  purpose TEXT,                                     -- ОБЯЗАТЕЛЕН для withdrawal (валидация в API)
  income_id INTEGER REFERENCES incomes(id) ON DELETE CASCADE ); -- если депозит создан распределением

CREATE TABLE IF NOT EXISTS obligations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('credit','utilities','mobile','internet','other')),
  default_amount INTEGER NOT NULL CHECK (default_amount >= 0),
  due_day INTEGER NOT NULL CHECK (due_day BETWEEN 1 AND 28),
  owner TEXT NOT NULL DEFAULT 'him' CHECK (owner IN ('him','her')),
  is_active INTEGER NOT NULL DEFAULT 1 );

CREATE TABLE IF NOT EXISTS obligation_payments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  obligation_id INTEGER NOT NULL REFERENCES obligations(id),
  month TEXT NOT NULL,                              -- 'YYYY-MM'
  paid_date TEXT NOT NULL, amount INTEGER NOT NULL CHECK (amount > 0),
  UNIQUE (obligation_id, month) );

CREATE INDEX IF NOT EXISTS idx_expenses_date ON expenses(date);
CREATE INDEX IF NOT EXISTS idx_incomes_date ON incomes(date);
CREATE INDEX IF NOT EXISTS idx_savings_date ON savings_tx(date);
```

### Сиды (вставлять только если таблицы пусты)

- categories (name / icon): Продукты `shopping-basket` · Транспорт `bus` · Кафе `coffee` · Дом `home` · Здоровье `heart-pulse` · Одежда `shirt` · Материалы (работа) `paintbrush` · Другое `circle-ellipsis`.

## 7. Бизнес-логика — чистые функции в `server/src/core/logic.ts` (покрыть тестами vitest)

### 7.1 `nextPayday(paydays: number[], today: string): { date: string; daysLeft: number }`

1. Кандидаты: каждый день `d` из `paydays` в текущем и следующем месяце → дата `cand`. Если `d` больше числа дней месяца — взять последний день месяца.
2. **Сдвиг на выходные:** если `cand` — суббота или воскресенье, сдвинуть **назад** на ближайшую пятницу.
3. Ответ — минимальная скорректированная дата `> today`. `daysLeft = cand - today` в днях (минимум 1).
4. Тесты обязаны покрыть: 19-е = суббота → 18-е (пятница); 19-е = воскресенье → 17-е; перенос через границу месяца; `paydays=[10,25]`; сегодня = день зарплаты → вернуть следующую дату, не сегодняшнюю.

### 7.2 `dailyBalance(user)` — остаток повседневных пользователя

```
Σ incomes.to_daily (user) + Σ transfers.amount (to_user = user)
− Σ transfers.amount (from_user = user) − Σ expenses.amount (user)
```
Может уйти в минус — это допустимо и отображается Кирпичом.

### 7.3 `perDay(user, today)` = `max(dailyBalance, 0) / daysLeft` (целочисленно, округление вниз).

**Заливка дуги `arcFill(user, today)` — точное определение:**
1. `P` = дата последнего дохода пользователя с источником `salary` или `advance` (доходы `nails`/`other` периодом не управляют). Если таких доходов нет — вернуть `1`, если `dailyBalance > 0`, иначе `0`.
2. `B0` = `dailyBalance`, вычисленный по всем записям с датой `≤ P` (записи в день P включаются целиком, во всех таблицах).
3. `arcFill = clamp(dailyBalance(today) / B0, 0, 1)`; если `B0 ≤ 0` — вернуть `1` при `dailyBalance > 0`, иначе `0`.
Переводы и доходы от маникюра после `P` могут поднять отношение выше 1 — это и есть причина clamp. Покрыть тестами: обычный период; пополнение переводом после P; B0 = 0; пользователь без зарплат.

### 7.4 Статус платежа в месяце M (`today` внутри M)

`paid` — есть запись в obligation_payments за M; иначе `overdue`, если `due_day < день(today)`; иначе `due_soon`, если `due_day − день(today) ≤ 3`; иначе `upcoming`. Для прошлых месяцев без оплаты — `overdue`; для будущих — `upcoming`.

### 7.5 Прочее

`savingsBalance` = Σ deposit − Σ withdrawal. Сводка «Платежи месяца»: `paidCount/totalCount`, `paidSum`, `plannedSum` (Σ default_amount активных), `reservedSum` = Σ `incomes.to_bills` доходов, дата которых лежит в месяце M, — отображается строкой «Отложено N из плановых P». Семейный сценарий: платежи оплачиваются сразу в день зарплаты, поэтому «отложено» и «оплачено» живут в одном календарном месяце; чек-лист месяца — это платежи, совершаемые в этом календарном месяце, независимо от того, за какой период выставлен счёт. Остаток `reservedSum − paidSum` никуда не переносится — он информационный.

### 7.6 Семейный код доступа

- Код задаётся переменной окружения `OCHAG_CODE` (обязательная; контейнер без неё не стартует, в логе — понятное сообщение).
- Fastify-хук `onRequest`: все пути `/api/*`, кроме `/api/auth/check`, требуют заголовок `x-ochag-code`, равный `OCHAG_CODE` (сравнение constant-time). Иначе — 401 `{ "error": "Нужен семейный код" }`.
- `POST /api/auth/check` `{code}` → `{ok:true}` или 401; на этот эндпоинт rate-limit 5 попыток/мин с IP (`@fastify/rate-limit`).
- Фронт: при 401 показывает экран ввода кода; верный код сохраняется в `localStorage` (`ochag_code`) и добавляется ко всем запросам. Это защита «от интернета», не от спецслужб — большего не строить.

## 8. API (все ответы JSON; ошибки — `{ "error": "человекочитаемое сообщение на русском" }` с кодом 400/404)

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/check` | Проверка семейного кода (раздел 7.6); единственный путь без заголовка `x-ochag-code` |
| `GET /api/state?user=him&today=YYYY-MM-DD` | Агрегат для главной: `{ user, currency, dailyBalance, perDay, payday:{date,daysLeft}, arcFill, upcomingBills:[≤3 со статусами], recentExpenses:[5], savingsBalance, isPaydayToday }` |
| `POST /api/expenses` · `DELETE /api/expenses/:id` | Тело: `{user, date, amount, categoryId, comment?}` |
| `POST /api/incomes` · `DELETE /api/incomes/:id` | Тело: `{user, date, source, amount, toDaily, toSavings, toBills, comment?}`; сервер проверяет сумму распределения и при `toSavings>0` создаёт `savings_tx(deposit, income_id)` в одной транзакции; DELETE каскадно удаляет связанный депозит |
| `POST /api/transfers` · `DELETE /api/transfers/:id` | `{fromUser, toUser, date, amount, comment?}` |

| `POST /api/savings/tx` · `DELETE /api/savings/tx/:id` | `{type, user, date, amount, purpose?}`; для `withdrawal` поле `purpose` обязательно (400 «Укажите цель снятия») |
| `GET /api/bills?month=YYYY-MM&today=YYYY-MM-DD` | `{ summary, items:[{obligation..., status, payment?}] }` |

| `GET /api/history?month=YYYY-MM` | Для «Итогов»: траты по категориям (по убыванию, с суммой и долей), список всех движений месяца, доходы по источникам, движение копилки, сводка платежей |

| `GET /api/export` | Полный дамп всех таблиц одним JSON (заголовок attachment, имя `ochag-backup-YYYY-MM-DD.json`) |
| `POST /api/import` | Принимает дамп, **полностью замещает** данные в одной транзакции; перед заменой пишет автокопию текущей БД в `data/pre-import-*.json` |

## 9. Экраны и поведение (вёрстка строго по токенам Документа 1, §7.2–7.5; mobile-first 360–430 px, десктоп — та же колонка по центру max-width 480 px)

Каркас: нижняя навигация «Сегодня · Платежи · Копилка · Итоги» + FAB «+». Первый запуск: экран семейного кода (одно поле + кнопка «Войти»; при 401 — «Код не подходит») → затем экран выбора профиля из двух крупных карточек «Он» / «Она» (цвета Север/Брусника). Код и профиль хранятся в `localStorage` (`ochag_code`, `ochag_user`) — дальше приложение открывается сразу на «Сегодня». Все суммы вводятся в целых рублях; кнопка «,» на пинпаде открывает ввод копеек (опционально). Отображение сумм: разряды через тонкий пробел, копейки — только ненулевые.

### 9.1 Сегодня (`/`)
Шапка: аватар-кружок профиля (нажатие — переключить профиль), слово «Очаг» (Unbounded), шестерёнка → настройки. Сигнатурная карточка: дуга 270° (SVG, Янтарь; <20% — Кирпич), внутри — «в день» крупно (40 px, tabular-nums), под дугой «Осталось X · до зарплаты N дн (дата)». Если `isPaydayToday` и доход за сегодня не внесён — плашка Хвоя «Сегодня зарплата — распределить?» → форма дохода. Ниже: «Ближайшие платежи» (≤3, статусные точки Мох/Янтарь/Кирпич, нажатие → вкладка Платежи) и «Последние траты» (5, свайп/долгое нажатие — удалить с confirm).

### 9.2 Быстрый ввод (FAB, bottom-sheet, вкладки Трата · Доход · Перевод)
**Трата (по умолчанию):** пинпад с крупной суммой → сетка категорий 4×2 (касание категории = сохранение) → тост «Записано», лист закрыт. Дата = сегодня (меняется по нажатию на дату), комментарий — опциональное поле без обязательности. **Доход:** сумма → источник (Зарплата/Аванс/Маникюр/Другое) → блок распределения: три поля «На платежи / В копилку / Себе на повседневные» (именно в таком порядке — он совпадает с реальным ритуалом семьи). Поле «На платежи» автозаполняется суммой **ещё не оплаченных** плановых платежей текущего месяца (Σ default_amount активных обязательств без отметки за месяц; редактируемо); «Себе» автозаполняется остатком; кнопка-ярлык «Всё в повседневные»; кнопка «Распределить» активна только при сходящейся сумме. После сохранения дохода с `toBills > 0` — тост с действием «Перейти к платежам →» (открывает вкладку Платежи, чтобы сразу прощёлкать оплаты). Для источника «Маникюр» по умолчанию всё в повседневные. **Перевод:** направление (Он→Она / Она→Он), сумма, готово.

### 9.3 Платежи (`/bills`)
Переключатель месяца ‹ Июнь 2026 ›. Сводка-строка: «Оплачено 4 из 7 · 3 800 ₽ из плановых 5 600 ₽ · отложено 5 000 ₽». Список: имя, срок «до 25-го», сумма (оплаченная или плановая), чек-кружок. Нажатие на кружок → мини-форма «Сумма (предзаполнена default_amount) · Дата (сегодня) · Оплатить». Нажатие на уже оплаченный платёж → та же форма в режиме правки: изменить сумму/дату (PATCH) или «Снять отметку» (confirm). Кнопка «Управлять платежами» → список обязательств с добавлением/правкой/архивом (поля: название, тип, плановая сумма, день срока, чей платёж).

### 9.4 Копилка (`/savings`)
Остаток крупно (Янтарь). Кнопки «Пополнить» и «Снять». Снятие требует цель (плейсхолдер «На что? — например: дача, маме лекарства»). История: строки с целью/источником, датой, цветным знаком +/−; записи, созданные распределением зарплаты, помечены «из зарплаты Его/Её» и не удаляются отсюда (удаляются только удалением дохода).

### 9.5 Итоги (`/history`)
Переключатель месяца. Блоки: «Повседневные траты» — сумма месяца и горизонтальные полосы по категориям (полоса Хвоя на подложке Лён, справа сумма и %); «Доходы» — по источникам, отдельно видна строка «Маникюр»; «Копилка» — +внесено / −снято за месяц и итоговый остаток; «Платежи» — оплачено X из Y на сумму Z; «Все операции» — хронологическая лента месяца (траты/доходы/переводы/копилка) с возможностью удаления (confirm).

### 9.6 Настройки (`/settings`)
Валюта (₽ / € / своя строка ≤3 символов); дни зарплат: Его — список дней, Её — список дней (чипы-числа, добавить/убрать, 1–28); категории (добавить: имя + выбор иконки из фиксированного набора 16 lucide-имён; архивировать); «Выйти» (стирает код и профиль из localStorage); «Скачать резервную копию (JSON)»; «Восстановить из копии» (file input + confirm «Текущие данные будут заменены»). Версия приложения внизу. Сам семейный код меняется только через переменную окружения на сервере — в UI лишь подпись об этом.

### 9.7 Состояния
У каждого экрана есть состояния: загрузка (скелетоны), ошибка сети («Нет связи с сервером. Проверьте интернет» + кнопка «Повторить»), пустое (короткое приглашение к действию в тоне брендбука). PWA офлайн: показывать оболочку с тем же сообщением об ошибке сети; офлайн-очередь записей **не делать**.

## 10. PWA и нефункциональные требования

- manifest: name «Очаг», short_name «Очаг», `display: standalone`, `theme_color #1E5C46`, `background_color #F2F1EC`, иконки 192/512 (сгенерировать простую: буква «О» Unbounded, белым на Хвое) + `apple-touch-icon`; мета `viewport-fit=cover`, отступы `env(safe-area-inset-*)` для iPhone.
- Шрифты Golos Text и Unbounded — **самохостинг** в `web/public/fonts` (woff2, кириллица+латиница), без запросов к Google Fonts в рантайме.
- Производительность: ответ любого GET < 50 мс на Raspberry Pi-классе железа (SQLite + индексы этого достаточно); бандл фронта < 350 КБ gzip.
- Доступность: видимый фокус, контраст текста ≥ 4.5:1, `prefers-reduced-motion`.
- Том `./data` примонтирован в контейнер; БД создаётся автоматически при первом старте.
- **Развёртывание на хостинге:** `docker-compose.yml` содержит сервис приложения и сервис **Caddy** как reverse-proxy с автоматическим HTTPS (Let's Encrypt) — домен задаётся переменной `OCHAG_DOMAIN`; переменные `OCHAG_CODE` и `TZ=Europe/Riga` обязательны. В корне репо — `README.md` с пошаговой инструкцией развёртывания на чистом VPS (5–7 команд) и инструкцией установки PWA на iPhone и Android со скриншот-описаниями словами.
- PWA: при наличии валидного HTTPS service worker обязан работать и на iOS; манифест и иконки — без условий по протоколу.

## 11. Приёмочные критерии (Definition of Done)

1. `docker compose up` с нуля (с заданными `OCHAG_CODE`, `OCHAG_DOMAIN`) → приложение доступно, БД и сиды созданы автоматически; запрос к `/api/state` без заголовка кода → 401.
2. Сценарий «быстрая трата»: открыть → «+» → сумма пинпадом (целые рубли) → касание категории = запись создана, главная цифра обновилась. Укладывается в 5 секунд.
3. Доход 4500 с распределением 2400/500/1600 (платежи/копилка/себе) создаёт income + депозит копилки; поле «На платежи» в форме автозаполнилось суммой неоплаченных плановых платежей месяца; «отложено» видно в сводке этого же месяца; удаление дохода удаляет и депозит; распределение с несходящейся суммой отклоняется с русским сообщением.
4. `nextPayday` и `arcFill`: все кейсы из §7.1 и §7.3 покрыты зелёными тестами (`npm test` в server).
5. Снятие из копилки без цели — 400; с целью — баланс и история корректны.
6. Платёж: отметка с изменённой суммой попадает в сводку; оплаченный платёж можно исправить (PATCH); статусы paid/due_soon/overdue/upcoming считаются от `today`, переданного клиентом, — при системном времени сервера UTC и клиентской дате «завтра» статусы соответствуют клиентской дате.
7. Перевод Он→Она 1000.00 уменьшает его dailyBalance и увеличивает её ровно на 100000 копеек.
8. Экспорт → стирание тома → импорт = идентичное состояние всех экранов.
9. Lighthouse PWA: устанавливаемость пройдена; на iPhone приложение открывается standalone без браузерного хрома.
10. В UI нет ни одного нетокенного цвета и ни одной англоязычной строки; суммы везде с tabular-nums, разряды через тонкий пробел, копейки показываются только ненулевые.
