# «Очаг» — Техническое задание v1.2
## Переработка интерфейса под эталонный прототип + модуль «Авто»

> **Кому:** агент-исполнитель (Opus).
> **База:** существующий репозиторий «Очаг» (Fastify + PostgreSQL, React 18 + TS + Vite + Tailwind + TanStack Query), реализованный по ТЗ v1.0 и v1.1 (Кредиты).
> **Эталон внешнего вида:** файл `Очаг_прототип.jsx` — интерактивный прототип, приложен к задаче. При любом расхождении между текстом этого ТЗ и прототипом по **визуалу** — прав прототип; по **данным и логике** — право это ТЗ.
> Это инкрементальное ТЗ: всё, что здесь не упомянуто, работает как раньше и не трогается.

## 1. Принцип навигации «двухэтажный дом» (закон проекта)

1. **Этаж 1** — 4 вкладки нижней навигации (денежное ядро).
2. **Этаж 2** — экраны модулей, открываемые из плитки «Разделы» на «Сегодня» (или контекстной карточки, как Кредиты с «Платежей»). С экрана модуля — только «← назад».
3. Глубже этажа 2 — только bottom-sheet (формы, детали). **Никаких** третьих уровней навигации, вложенных табов и новых пунктов меню.
4. Новый модуль в будущем = новая плитка в «Разделах» + один экран. Это правило фиксируется в README проекта.

Активная вкладка при нахождении на экране модуля: «Сегодня» для Авто, «Платежи» для Кредитов (см. прототип, функция `Nav`).

## 2. Каркас UI (блок A)

### 2.1 Плавающая навигация
Заменить прижатую к низу панель на «таблетку»:
- `position: fixed; left: 14px; right: 14px; bottom: calc(14px + env(safe-area-inset-bottom, 0px))`;
- фон `#FFFFFF`, радиус 26px, тень `0 8px 28px rgb(38 40 43 / .18)`;
- 4 кнопки: иконка (lucide-react: `Home`, `ListChecks`, `PiggyBank`, `BarChart3`) + подпись 10.5px;
- активная — цвет Хвоя `#1E5C46`, неактивная — Дым `#7A7E83`.

FAB «+» (56px, Хвоя) — над таблеткой справа: `bottom: calc(88px + env(safe-area-inset-bottom, 0px))`, как в прототипе.

Контент экранов получает `padding-bottom: calc(110px + env(safe-area-inset-bottom, 0px))`, чтобы ничего не пряталось под навигацией.

### 2.2 Safe-area и PWA
- В `index.html`: `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` — без `viewport-fit=cover` env-отступы всегда 0.
- Проверить манифест: `display: "standalone"` (должно быть из v1.0).

### 2.3 Микродвижение (единый набор, других анимаций не вводить)
| Имя | Где | Параметры |
|---|---|---|
| `fade` | появление экрана | opacity 0→1 + translateY(6px), 220ms ease |
| `rise` | bottom-sheet | translateY(40%)→0, 260ms cubic-bezier(.2,.9,.3,1) |
| `emberPulse` | «уголёк» на дуге и в ленте погашения | opacity 1→.45→1, 1.8s infinite |
| `grow` | столбики графиков | scaleY(0)→1, 600ms, transform-origin bottom |
| `press` | все кнопки/карточки | active: scale(.97) + opacity .7, 120ms |
| count-up | крупные суммы (дуга, Кредиты, Копилка) | 600–800ms, easeOutCubic, через rAF |

Обязательно: `@media (prefers-reduced-motion: reduce)` отключает всё перечисленное (count-up показывает конечное значение сразу).

### 2.4 Мелочи
- Все числовые суммы — класс с `font-variant-numeric: tabular-nums`.
- Тост: тёмная плашка (Уголь, радиус 14) над навигацией, 1.8s; компонент принимает произвольный текст («Записано ✓», «Зарядка записана ⚡»).
- Скруглённые статус-точки 9px — единый компонент `StatusDot`, цвета: paid `#5E8C61`, due_soon `#D9A441`, overdue `#C0492F`, upcoming `#C9C7BF`.

## 3. Экран «Сегодня» (блок B)

Порядок секций сверху вниз (см. прототип, компонент `Today`):
1. Шапка: аватар профиля (тап — переключение Он/Она), логотип «Очаг» (Unbounded), шестерёнка настроек.
2. **Карточка-дуга**: дуга 270° (старт 225°), заполнение `arcFill` из v1.0; на конце дуги — кружок-«уголёк» 4.5px с `emberPulse`. В центре — «в день» + сумма (count-up). Под дугой: «Осталось N ₽ · до зарплаты K дн (дата)». При `arcFill < 0.2` дуга и сумма — Кирпич.
3. Баннер «Скоро зарплата — {дата} [Распределить]» (фон Хвоя) — показывается, если до зарплаты ≤ 3 дней; кнопка открывает шторку на вкладке «Доход».
4. «Ближайшие платежи» — 3 неоплаченных, тап ведёт на вкладку «Платежи».
5. **Плитка «Разделы»** — см. §3.1.
6. «Последние траты» текущего профиля (4 шт.).

### 3.1 Плитка «Разделы»
- CSS grid `1fr 1fr`, gap 10px; плитка — белая карточка (радиус 20): иконка в цветной «капле» 34px (радиус 11), заголовок 14.5px/600, подзаголовок 12px Дым с **живой цифрой**.
- Конфиг модулей — массив в одном файле `web/src/modules.ts`:
  ```ts
  type Tile = { key: string; icon: LucideIcon; tint: string; title: string;
                sub: (data: TilesData) => ReactNode; route?: string; soon?: boolean };
  ```
- v1.2 содержит: **Авто** (`route: '/car'`, sub: «ТО через N км» либо ближайший срок), **Кредиты** (`route: '/credits'`, sub: «осталось X ₽» из `GET /api/credits` summary), **Покупки** и **Счётчики** — `soon: true`, opacity .55, тап показывает тост «Скоро 🌱».
- Данные для подзаголовков — одним запросом `GET /api/tiles?today=` → `{ car: {nextHint}, credits: {totalLeftToPay} }` (сервер собирает из готовых функций; не плодить N запросов с главного экрана).

## 4. Экраны «Платежи» и «Кредиты» (блок C)

### 4.1 Платежи
- Строки чек-листа: StatusDot + название + «до N-го · {статус словами}» + сумма + кружок-галка (заполненный Мох у оплаченных). Подпись просрочки — Кирпич.
- Карточка-вход «Кредиты» под чек-листом: капля 🪵 на янтарном фоне, подзаголовок «осталось выплатить X ₽», шеврон. Ведёт на `/credits`.

### 4.2 Кредиты (визуальная доработка экрана из v1.1)
- Сводка: подпись-капс «Осталось выплатить», сумма 42px с count-up, строка «в месяц X · кредитов N».
- **График «Станет легче»** (карточка под сводкой): столбики месячной нагрузки — «сейчас» (Янтарь) и по одному столбику после каждого будущего закрытия (Хвоя), последний при нагрузке 0 — Мох с подписью «свобода». Данные считаются на клиенте из ответа `GET /api/credits`: группировка `items` по `closeMonth`, последовательное вычитание `monthly_load` закрывающихся. Столбики — `grow`, высота пропорциональна нагрузке (мин. 6px).
- **Лента погашения** в каждой карточке кредита: ряд сегментов (flex, gap 1.5–2.5px, высота 7px, радиус 4), по одному на платёж: `i < paymentsMade` — Хвоя; `i === paymentsMade` и кредит не закрыт — Янтарь с `emberPulse`; остальные — `#E7E5DE`. `aria-label="выплачено X из Y"`.
- Под лентой: «выплачено **X из Y**» и «закроется в **{closeMonth}**» (или «выплачен 🎉» Мохом).
- Тап по карточке раскрывает детали: платёж/мес, переплата (0 — Мохом), «№ договора · открыт {дата} · {назначение}». Сортировка карточек — по `paymentsLeft` возр. (из v1.1).

## 5. Модуль «Авто» — данные и сервер (блок D)

Машина в семье одна (v1.2). Все суммы — копейки (integer), энергия — ватт-часы (integer), пробег — километры (integer), даты — строки `YYYY-MM-DD`. «Сегодня» всегда приходит от клиента параметром `today` — серверу запрещён `new Date()` в бизнес-логике (закон из v1.0).

### 5.1 Схема БД (миграция №…, добавить в `db.ts`)

```sql
CREATE TABLE IF NOT EXISTS vehicle (
  id           INTEGER PRIMARY KEY CHECK (id = 1),   -- единственная строка
  name         TEXT NOT NULL,                        -- «DongFeng Vigo»
  trim         TEXT,                                 -- «480 Max»
  plate        TEXT,
  is_ev        BOOLEAN NOT NULL DEFAULT TRUE,
  start_odo    INTEGER NOT NULL DEFAULT 0,           -- пробег при покупке, км
  bought_date  TEXT,
  warranty_till TEXT,                                -- «2029-02-24»
  warranty_km  INTEGER,                              -- 100000
  battery_wh   INTEGER,                              -- 51870
  tires        TEXT,                                 -- «215/55 R18»
  petrol_l_per_100_x10 INTEGER NOT NULL DEFAULT 80,  -- 8.0 л/100 — для сравнения
  petrol_price        INTEGER NOT NULL DEFAULT 236,  -- копейки за литр
  home_tariff         INTEGER NOT NULL DEFAULT 27,   -- копейки за кВт·ч (справочно для подстановки)
  created_at   TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS odo_readings (
  id    SERIAL PRIMARY KEY,
  date  TEXT NOT NULL,
  km    INTEGER NOT NULL CHECK (km >= 0)
);

CREATE TABLE IF NOT EXISTS charges (
  id         SERIAL PRIMARY KEY,
  date       TEXT NOT NULL,
  place      TEXT NOT NULL CHECK (place IN ('home','network','other')),
  place_name TEXT,                                   -- «Malanka», «у тёщи»
  wh         INTEGER NOT NULL CHECK (wh > 0),
  amount     INTEGER NOT NULL CHECK (amount >= 0),   -- копейки
  by_user    TEXT NOT NULL CHECK (by_user IN ('him','her')),
  expense_id INTEGER REFERENCES expenses(id)         -- связанная трата
);

CREATE TABLE IF NOT EXISTS car_deadlines (
  id            SERIAL PRIMARY KEY,
  title         TEXT NOT NULL,                       -- «ТО у дилера», «Шины на зиму»
  due_date      TEXT,                                -- срок по дате
  due_km        INTEGER,                             -- и/или по пробегу
  repeat_months INTEGER,                             -- повтор: + месяцев после выполнения
  repeat_km     INTEGER,                             -- повтор: + км после выполнения
  note          TEXT,
  done_date     TEXT,                                -- последнее выполнение
  done_km       INTEGER,
  CHECK (due_date IS NOT NULL OR due_km IS NOT NULL)
);
```

`charges` и связь с бюджетом: при создании зарядки сервер **в одной транзакции** создаёт обычную трату (`expenses`) с категорией «Авто» (если категории нет — создать при миграции), суммой `amount`, профилем `by_user`, и пишет её id в `charges.expense_id`. Удаление зарядки удаляет связанную трату (и наоборот запрещено: трату с `expense_id`-связью удалять только через удаление зарядки — на клиенте такие траты помечены ⚡ и не имеют кнопки удаления в общем списке).

Добавить `vehicle`, `odo_readings`, `charges`, `car_deadlines` в `TABLES` экспорта/импорта (`routes/data.ts`) — после `credits`.

### 5.2 Чистые функции (`server/src/core/logic.ts` + тесты в `logic.test.ts`)

```ts
carStats(charges: Charge[], odoReadings: OdoReading[], vehicle: Vehicle): {
  currentOdo: number;        // максимум km из odo_readings, иначе start_odo
  totalKm: number;           // currentOdo - start_odo, не меньше 0
  whTotal: number; costTotal: number;          // по всем зарядкам
  per100Wh: number | null;   // whTotal / totalKm * 100, null если totalKm < 100
  cost100: number | null;    // costTotal / totalKm * 100 (копейки), null если totalKm < 100
  petrolCost100: number;     // petrol_l_per_100_x10/10 * petrol_price
  savedVsPetrol: number | null; // (petrolCost100 - cost100) / 100 * totalKm, копейки; null если cost100 null
}
```
Замечание: при `totalKm < 100` км статистика «ещё копится» — клиент показывает прочерки с подписью «накатайте 100 км».

```ts
deadlineStatus(d: CarDeadline, today: string, currentOdo: number):
  'overdue' | 'due_soon' | 'upcoming'
```
- `overdue`: `due_date < today` ИЛИ `due_km <= currentOdo` (что задано);
- `due_soon`: до `due_date` ≤ 30 дней ИЛИ `due_km - currentOdo` ≤ 1000 км;
- иначе `upcoming`. Если заданы и дата, и пробег — берётся **худший** (более тревожный) статус: правило «что наступит раньше».

```ts
completeDeadline(d, doneDate, doneKm): CarDeadline
```
- пишет `done_date/done_km`; если задан `repeat_months` — новый `due_date = done_date + repeat_months мес`; если `repeat_km` — новый `due_km = doneKm + repeat_km`; без повторов — сроки обнуляются (карточка уходит в «выполнено»).

**Обязательные тест-кейсы:** статус по дате/по км/по обоим (худший побеждает); границы 30 дней и 1000 км; повтор по месяцам с переходом через год; повтор по км; `carStats` при totalKm<100; `carStats` с несколькими показаниями одометра не по порядку дат; экономия отрицательной не бывает на дефолтных настройках, но функция должна корректно отдавать отрицательное значение, если зарядки дороже бензина (сеть-only).

### 5.3 API (`routes/car.ts`, всё под `x-ochag-code`)

| Метод | Путь | Тело/параметры | Ответ |
|---|---|---|---|
| GET | `/api/car?today=` | — | `{ vehicle, stats: carStats(...), deadlines: [{...d, status}] (сорт.: overdue, due_soon, upcoming), charges: последние 20 }`; `vehicle: null`, если не создана |
| PUT | `/api/car` | поля vehicle (zod, частичное обновление) | vehicle; создаёт строку id=1 при первом вызове |
| POST | `/api/car/odo` | `{ date, km }` | reading; 400 если km меньше последнего показания более ранней даты |
| POST | `/api/car/charges` | `{ date, place, place_name?, wh, amount, by_user }` | charge (+ создана трата, см. §5.1) |
| DELETE | `/api/car/charges/:id` | — | `{ok:true}` (+ удалена связанная трата) |
| POST | `/api/car/deadlines` | `{ title, due_date?, due_km?, repeat_months?, repeat_km?, note? }` | deadline |
| PUT | `/api/car/deadlines/:id` | те же поля | deadline |
| POST | `/api/car/deadlines/:id/done` | `{ date, km? }` | deadline после `completeDeadline` |
| DELETE | `/api/car/deadlines/:id` | — | `{ok:true}` |

`GET /api/tiles?today=` (см. §3.1) переиспользует `carStats` + `creditCalc`, ничего не дублирует.

### 5.4 Сиды
При пустой таблице `vehicle` ничего не сидировать (модуль спит, плитка показывает «настроить →» и ведёт на форму машины). Дефолтные дедлайны создавать **после** создания машины: «ТО у дилера» (repeat по согласованию пользователя в форме: предложить 15 000 км / 12 мес), «Гостехосмотр», «Страховка», «Шины: зима» (15 октября, repeat 12 мес), «Шины: лето» (15 апреля, repeat 12 мес) — все, кроме шин, с пустыми сроками «заполните даты».

## 6. Модуль «Авто» — экран (блок D, клиент)

Маршрут `/car`, вход с плитки. Вёрстка — строго по прототипу (компоненты `Auto`, `Road`):

1. **Гараж**: имя + комплектация + номер; одометр 38px по центру — тап превращает в `<input type="number" inputmode="numeric">`, blur/Enter → `POST /api/car/odo` (дата = сегодня клиента) → инвалидация запроса. Под ним подпись «нажмите, чтобы обновить пробег».
2. **«Дорога пробега»** (SVG, сигнатура экрана): линия 0 → `warranty_km`, пройденное — Хвоя, точка-машинка на `currentOdo` с подписью пробега, янтарный флажок на ближайшем `due_km`-дедлайне («ТО 15 000»), серый финиш «гарантия 100 000». Если `warranty_km` не задан — шкала до ближайшего `due_km` × 1.2.
3. **Зарядка**: карточка с тремя числами из `stats` — `cost100` («стоит 100 км»), `per100Wh`/1000 с одним знаком («кВт·ч / 100 км»), `savedVsPetrol` зелёным («vs бензин», с плюсом). Кнопка «⚡ Зарядился» — bottom-sheet: кВт·ч (пинпад-стиль), сумма, сегмент-переключатель Дом / Сеть / Другое (+имя), при «Дом» сумма предзаполняется `wh × home_tariff` (редактируемая). Журнал: 🏠 зелёная капля для дома, ⚡ янтарная для сети, строка «{место} · {дата} · {кВт·ч} кВт·ч · −{сумма}», свайп/долгий тап — удалить.
4. **Сроки**: карточки дедлайнов со StatusDot и человекочитаемым hint: для км-сроков «при 15 000 км · осталось N км», для дат «до {дата}», для обоих — обе части. Тап — sheet редактирования + кнопка «Выполнено ✓» (`/done`, спрашивает текущий пробег, если у срока есть `repeat_km`).
5. **Батарея** (только при `is_ev`): строка гарантии «до {warranty_till} · {warranty_km − currentOdo} км»; янтарная подсказка про LFP-калибровку: «раз в 2–3 недели зарядите до 100%» + «Последний раз: {дата зарядки с пометкой 100%}» — в форму зарядки добавить чекбокс «зарядил до 100%» (поле `full BOOLEAN DEFAULT FALSE` в `charges`).
6. **«Во сколько обходится {месяц}»**: суммы трат категории «Авто» текущего месяца, сгруппированные: «Зарядки» (по `expense_id`-связи) и «Прочее» + итог. Эти траты уже входят в Итоги — блок ничего не дублирует в БД, только группирует.

Терминология (словарь): «Зарядился», «стоит 100 км», «vs бензин», «Дорога пробега» (внутр.), «Сроки», «Выполнено ✓». Не употреблять «транзакция», «дедлайн», «лог».

## 8. Приёмочные критерии

1. Навигация — плавающая таблетка, не перекрывается системными панелями (проверка: Chrome Android с нижней строкой, iPhone Safari); контент докручивается до конца.
2. На «Сегодня» — плитка «Разделы» 2×2; Авто и Кредиты ведут на экраны, «Покупки»/«Счётчики» — заглушки с тостом; цифры в подзаголовках живые (одним запросом `/api/tiles`).
3. Дуга: уголёк пульсирует, сумма «в день» оживает count-up'ом; при reduced-motion — статично и мгновенно.
4. Кредиты: лента погашения сегмент-в-платёж, текущий пульсирует Янтарём; график «Станет легче» заканчивается столбиком «свобода»; цифры сходятся с `creditCalc`.
5. `vehicle` создаётся через PUT, плитка до создания зовёт «настроить →».
6. Ввод одометра с экрана работает; «Дорога пробега» сдвигает машинку и пересчитывает «осталось N км» у ТО без перезагрузки.
7. Зарядка создаёт трату категории «Авто» (видна в Итогах и в «Последних тратах» с ⚡), удаление зарядки убирает трату; у траты-зарядки нет самостоятельного удаления.
8. Три числа статистики совпадают с ручным расчётом на контрольном наборе (зафиксировать в тесте интеграционно: 5 зарядок + 2 показания одометра); при пробеге < 100 км — прочерки с подписью.
9. `deadlineStatus`: срок «по дате или пробегу» загорается по худшему из условий; «Выполнено ✓» с повтором создаёт следующий срок (дата+12 мес / км+15 000).
10. Экспорт→очистка→импорт сохраняет машину, показания, зарядки (со связями на траты) и сроки.
11. `npm test` зелёный: все кейсы §5.2 покрыты.
